# Local HTTPS dev setup (polaris.local / id.polaris.local)

This sets up locally-trusted HTTPS for the app and Keycloak using [mkcert](https://github.com/FiloSottile/mkcert),
so OAuth2 redirects between Swagger UI and Keycloak work without browser cert warnings breaking the flow.

## Repo layout expected

```
repo-root/
├── scripts/
│   └── setup-local-https-mac-m1.sh
├── nginx/
│   ├── nginx.conf
│   └── certs/          <- generated by the script, gitignored
├── rootCA.pem           <- generated by the script, gitignored
├── docker-compose.yml
└── Dockerfile
```

## One-time setup (each developer runs this once)

```bash
./scripts/setup-local-https-mac-m1.sh
```

This will:
1. Install Homebrew if missing.
2. Install `mkcert` + `nss` via Homebrew.
3. Install mkcert's local CA into your system/browser trust stores (`mkcert -install`).
4. Add `polaris.local` and `id.polaris.local` to `/etc/hosts` (asks for `sudo`).
5. Generate a cert covering both domains into `nginx/certs/`.
6. Copy the mkcert root CA to `rootCA.pem` at repo root, so it can be baked into the app's Docker image
   (needed so the JVM trusts Keycloak's cert when validating JWTs over HTTPS — see Dockerfile snippet below).

Safe to re-run — it skips any step already satisfied.

## Add to .gitignore

Certs and keys should never be committed — mkcert regenerates them identically on any machine that runs the script:

```gitignore
nginx/certs/
rootCA.pem
```

## Dockerfile: trust the mkcert CA inside the app container

Add this to your app's `Dockerfile` so Spring's `JwtDecoder` can fetch Keycloak's JWK set over HTTPS
without a TLS trust error:

```dockerfile
COPY rootCA.pem /usr/local/share/ca-certificates/mkcert-rootCA.crt
RUN keytool -importcert -noprompt -trustcacerts \
    -alias mkcert-root \
    -file /usr/local/share/ca-certificates/mkcert-rootCA.crt \
    -keystore "$JAVA_HOME/lib/security/cacerts" \
    -storepass changeit
```

> Dev-only convenience — never ship an image trusting a locally-generated CA to any non-local environment.

## Verify

```bash
docker compose up --build
```

Then visit `https://polaris.local/swagger-ui/index.html` — the padlock should show a valid, trusted
certificate (no warnings), and clicking **Authorize** should redirect to `https://id.polaris.local` cleanly.

## Troubleshooting

| Symptom | Likely cause |
|---|---|
| Browser still warns about the cert | Re-run `mkcert -install`, then fully quit and reopen the browser (Chrome/Firefox cache CA trust at launch). |
| `app` container can't validate tokens (SSL trust error) | `rootCA.pem` wasn't copied into the image — rebuild after confirming the file exists at repo root. |
| 401 with `iss claim is not valid` | Issuer mismatch — confirm `SPRING_SECURITY_OAUTH2_RESOURCESERVER_JWT_ISSUER_URI` and `SPRINGDOC_OAUTH_ISSUER` both read `https://id.polaris.local/realms/polaris` exactly, no trailing slash. |
| `id.polaris.local` unreachable from inside the `app` container | Confirm `extra_hosts: ["id.polaris.local:host-gateway"]` is set on the `app` service in `docker-compose.yml`. |
